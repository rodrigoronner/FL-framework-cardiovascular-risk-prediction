# DP-FedAdam: auditing and allocating per-hospital privacy budgets in differentially private federated learning

> **Paper:** *Interpretable and Fairness-Aware Differentially Private Federated Learning for Cardiovascular Risk Prediction: A Fuzzy Approach to Practical Privacy Budgets* — Applied Soft Computing, manuscript ASOC-D-26-13458, **revision R1**.

> **Note on anonymization:** author names and affiliations are not given here, for double-anonymized review.

This repository contains the code, data, per-run results and analysis scripts behind every number, table and figure of the revised manuscript. The first-submission pipeline (Flower orchestration, SMOTE, Optuna search, fitted preprocessing, the IEEE-CHD cohort) was removed because the review showed that it invalidated the reported privacy budgets; it remains in the git history.

## What the study does

Four public cardiac cohorts with no shared patients act as hospitals. Each trains a shared 22–64–32–1 network with DP-SGD (Opacus, Poisson sampling) and the server aggregates with FedAdam (default hyperparameters of Reddi et al., 2021). A Rényi accountant that models exactly the executed sampler computes every site's privacy budget.

* **Audit.** Under a common lot size of 32, the smallest site (H1, 211 training records) spends ε = 8.22 and the others ≈ 4.2 (δ = 10⁻⁵, σ = 2.5, 100 rounds, one local epoch): a 2.01× spread. With Poisson sampling a site's budget depends only on its number of lots per epoch.
* **Allocation rules** (`experiments/revision_runner.py::allocate`): fixed lots; exact equalization (same lots per epoch everywhere); size-proportional; the fuzzy lot-size controller of the first submission (`dpfedadam/fuzzy_fairness.py`); and cap-based rules — *no harm* (only sites above the cap shrink their lots) and a *headroom fraction* f that lets the other sites enlarge theirs.
* **Fuzzy headroom policy** (`experiments/headroom_study.py`): a nine-rule Mamdani policy that chooses f from two public properties of the federation, tested in a pre-specified study on twelve federations. Its protocol was frozen before any run: `experiments/headroom_study_protocol.md` (records the date and the SHA-256 of the code).

Main results (20 partitions × 3 training seeds unless stated): no harm lowers the worst case from 8.22 to 5.98 and raises macro AUC from 0.777 to 0.787 without raising any other site's budget; exact equalization reaches 0.792 by raising the budgets of the three larger sites. In the pre-specified study the fuzzy policy met all three criteria (matched always-equalize, 0.784 vs 0.782, with mean client ε 5.81 vs 5.98, and beat never-spend by 0.006), while a fixed half-headroom rule did equally well.

## Repository layout

```
data/                     four client CSVs + converters from the raw public files (see data/README.md)
dpfedadam/
  data_utils.py           loading, harmonization, data-independent preprocessing, train-fold feature ranking
  model.py                22-64-32-1 network
  evaluation.py           validation-calibrated threshold and test metrics
  rdp_accountant.py       per-site Rényi accounting of the executed Poisson-subsampled Gaussian mechanism
  epsilon_matched.py      exact equalization / cap search (largest lot with eps <= target)
  proportional_fairness.py  size-proportional lots
  fuzzy_fairness.py       fuzzy lot-size controller (first submission) with sensitivity hooks
experiments/
  revision_runner.py      single-process federated simulator and every experiment suite
  revision_analysis.py    paired tests, Holm, Friedman/Nemenyi, MIA audit, subgroup recall
  revision_extras.py      deterministic analyses (controller sensitivity, rule firing, noise variance, horizon)
  revision_report.py      writes every table body and figure of the manuscript from the CSV files
  headroom_study.py       pre-specified headroom study (federations, fuzzy policy, analysis)
  headroom_study_protocol.md  frozen protocol of that study
  check_data_integrity.py checks that no patient is shared between or duplicated within clients
  momentum_noise_check.py numerical check of the first-moment variance identity
results_revision/         one CSV row per training run (3,540 runs) and the analysis reports
```

Per-run prediction files (`results_revision/preds/`, ~75 MB) are not tracked; they are regenerated by the runner and are only needed for ROC curves, the membership-inference audit and subgroup recall.

## Reproducing the results

```bash
python -m venv .venv && .venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m experiments.check_data_integrity        # must print RESULT: OK
.venv/bin/python -m experiments.revision_runner --list      # suites and run counts
.venv/bin/python -m experiments.revision_runner --suite main_default --workers 8
#   other suites: main, dp_optimizers, nodp, nodp_default, eps_targets, scalability,
#   graded, headroom, graded_headroom, noharm_targets, headroom_study, headroom_study_fuzzy
.venv/bin/python -m experiments.revision_analysis > results_revision/analysis_report.txt
.venv/bin/python -m experiments.headroom_study    > results_revision/headroom_study_report.txt
.venv/bin/python -m experiments.revision_extras
.venv/bin/python -m experiments.momentum_noise_check
.venv/bin/python -m experiments.revision_report --out <manuscript source folder>
```

Runs are deterministic given (partition seed, training seed, configuration); a finished run is skipped when its `run_id` is already in the suite's CSV. The budget counted by Opacus during training equals the audited budget in all 3,060 DP runs (`eps_max_abs_diff` column).
